# 日本株からnoteの下書きへ

依頼を受けたら、調査からnote上の保存確認まで一続きで実行する。Web検索と利用可能なブラウザ操作機能を使う。専用API、MCP、追加パッケージは要求しない。売買や注文は行わない。

## 1. 銘柄を選ぶ

- 日本時間の今日を確認する。直近の値動き、決算、適時開示、ニュースから候補を2～3銘柄だけ探す。ユーザー指定銘柄があればそれを優先する。
- 会社名と証券コード、話題の日付、記事の切り口を確認し、公開資料が揃う1銘柄を選ぶ。市場休場日には直近取引日を示す。
- 大きな値動きとニュースが同日にあっても、原因と断定しない。

## 2. 記事に必要な分だけ調べる

- 株価、前日比または一定期間の値動き、出来高、PERなどの代表指標、売上・利益、最近の材料を調べる。会社IR・適時開示・取引所などの一次資料を優先し、相場データは提供元と基準日を残す。
- 予想／実績、連結／単体、通期／四半期、決算期、単位を混ぜない。取得できない項目は推測で埋めず、記事の論点に不要なら省く。特にPERは定義と基準日を確認できない場合は書かない。
- 確認できた事実、筆者の見方、未確認事項を分け、強気材料と気になる点をそれぞれ一つ以上見つける。根拠URLと公開日・取得日をメモする。

## 3. 書いて点検する

- `references/article-template.md` を参考に、数字や出来事を入口にした自然な日本語の記事を書く。テンプレートの節数や文字数に無理に合わせない。
- `references/checks.md` で会社名、証券コード、主要数値と時点、ニュースの時点、原因の表現、免責を確認する。検証できない主要数値や原因の断定は削る。
- 記事末尾に主な参照元URLと取得日、日本時間の調査日時、「投資助言ではない」旨を入れる。

## 4. ブラウザでnoteに保存する

- 使えるブラウザ操作機能でnoteを開き、ログイン状態を画面で確かめる。ログインしていない、CAPTCHAが出た、ブラウザ操作が使えない場合はその状態と未完了部分を伝える。ログインやCAPTCHAの突破は自動化しない。
- 新規テキスト記事を開き、タイトルと本文を入力する。画面要素はその都度確認し、固定のセレクタやURLを決め打ちしない。
- 既定は「下書き保存」を実行する。自動保存表示だけで完了とせず、保存完了表示または下書き一覧・再表示でタイトルと本文が残っていることを確かめる。成否不明なら同じ記事を重複作成せず、まず一覧を確認する。
- ユーザーが今回の依頼で明示的に「公開して」と指示した場合だけ、記事を点検後に公開する。「投稿して」「記事にして」のみなら下書きにする。
- 完了時は銘柄名・証券コード、下書き／公開の別、確認できたnoteのURLまたは画面上の状態を報告する。確認できないURLや保存状態を作らない。
